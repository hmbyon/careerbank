# CareerBank Backend (FastAPI)

FastAPI backend for 경험은행 (CareerBank). See `../SPEC.md` for the full product spec.

## Stack

- FastAPI + SQLAlchemy 2.x (SQLite locally, Postgres in production)
- JWT auth (`python-jose`) + bcrypt password hashing (`passlib`)
- Google Gemini (`google-generativeai`) for AI features, with non-AI fallbacks for
  every AI use case so the app never hard-fails without a Gemini key

## 1. Local run

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# edit .env if you want to set GEMINI_API_KEY, JWT_SECRET, etc.
# (all values are optional locally — the app runs with sane defaults)

uvicorn app.main:app --reload --port 8000
```

- API base URL: `http://localhost:8000/api`
- Health check: `http://localhost:8000/health`
- Interactive docs: `http://localhost:8000/docs`

With no `DATABASE_URL` set, the app uses a local SQLite file `backend/careerbank.db`
(created automatically on first run — no migrations needed, tables are created via
`Base.metadata.create_all()` at startup).

With no `GEMINI_API_KEY` set, interview questions use the built-in Korean question
bank, essay-experience matching uses a keyword-overlap heuristic, and draft
generation uses a simple template — every endpoint still works end-to-end.

### Getting a free Gemini API key

1. Go to https://aistudio.google.com/apikey
2. Sign in with a Google account and click "Create API key" (free tier).
3. Put it in `.env` as `GEMINI_API_KEY=...`. Restart the server to pick it up.

## 2. Deploying to Render + Neon (free tier)

### 2a. Create a free Postgres database on Neon

1. Go to https://neon.tech, sign up, and create a new project.
2. Copy the connection string it gives you (starts with `postgresql://`).
   Render also accepts the `postgres://` form — the app rewrites it automatically.

### 2b. Deploy the backend to Render

Option A — using `render.yaml` (recommended):

1. Push this repo to GitHub.
2. In Render, click **New > Blueprint**, point it at the repo, and select
   `backend/render.yaml`.
3. Render will build the Docker image from `backend/Dockerfile`.
4. Set the env vars it prompts for (`DATABASE_URL`, `GEMINI_API_KEY`, `FRONTEND_URL`).
   `JWT_SECRET` is auto-generated by the blueprint.

Option B — manual web service:

1. In Render, click **New > Web Service**, connect the repo, set the root
   directory to `backend/`, and choose **Docker** as the environment (it will
   pick up `backend/Dockerfile` automatically).
2. Set environment variables under the service's **Environment** tab:
   - `DATABASE_URL` — the Neon connection string from step 2a
   - `JWT_SECRET` — a long random string (e.g. `openssl rand -hex 32`)
   - `GEMINI_API_KEY` — your Gemini key (optional but recommended)
   - `GEMINI_MODEL` — `gemini-2.0-flash` (default, can leave unset)
   - `FRONTEND_URL` — your deployed Vercel frontend URL (e.g. `https://careerbank.vercel.app`)
3. Set the health check path to `/health`.
4. Deploy. Render's free plan will spin the service down when idle and cold-start
   on the next request — this is expected on the free tier.

### 2c. Verify

```bash
curl https://<your-render-service>.onrender.com/health
# {"status":"ok"}
```

## 3. Environment variables reference

| Var | Required | Default | Notes |
|---|---|---|---|
| `DATABASE_URL` | no | (SQLite file) | Set in production (Neon/Supabase Postgres URL) |
| `JWT_SECRET` | yes in prod | random per-process | Must be set and stable in production |
| `GEMINI_API_KEY` | no | (unset) | AI features fall back to non-AI logic if unset |
| `GEMINI_MODEL` | no | `gemini-2.0-flash` | |
| `FRONTEND_URL` | no | `http://localhost:3000` | Used for CORS allow-origin |
| `JWT_EXPIRE_MINUTES` | no | `1440` | Access token lifetime |

## 4. Project layout

```
backend/
  app/
    main.py            FastAPI() app, CORS, routers, create_all, /health
    database.py        engine/session/Base, DATABASE_URL handling
    models.py          SQLAlchemy models (6 tables + 2 enums)
    schemas.py          Pydantic request/response models
    security.py           password hashing, JWT, get_current_user
    routers/
      auth.py, dashboard.py, timelines.py, interview.py,
      experiences.py, essay_questions.py, matches.py
    services/
      gemini.py           Gemini integration + fallbacks (all 3 AI use cases)
      matching.py          experience-summary + scoring helpers for essay matching
  requirements.txt
  Dockerfile
  render.yaml
  .env.example
```
